2. The whole of Kafka on one page

Data modelRecords go to topics. Topics are split into partitions (ordered logs). Each record has an offset inside its partition. Same key, same partition.
DurabilityEach partition has RF copies on different brokers: one leader, the rest followers. ISR = copies that are caught up. acks=all plus min.insync.replicas=2 with RF 3 survives one broker loss.
ConsumptionConsumers pull. A consumer group shares partitions (one owner each); groups are independent. Position = committed offset; lag = log end minus committed.
StoragePartitions are folders of segment files. Retention deletes whole closed segments by time or size; compaction keeps the latest value per key.
Control planeKRaft controllers (a Raft quorum) track topics, leaders and ISR. They need a majority alive.
On KubernetesStatefulSet (identity + disk), headless service (per-broker DNS), anti-affinity (one broker per node), PDB (never lose two at once).

6. Where to go next

Kafka Connect

Move data between Kafka and databases, object storage or search with ready-made connectors and no code.

Schema Registry

Version your message formats (Avro, Protobuf, JSON Schema) so producers and consumers can evolve safely.

Stream processing

Kafka Streams, ksqlDB or Flink: joins, windows and aggregations over live topics.

Security

TLS encryption, SASL authentication and ACLs. Required before any shared or production use.

Observability

JMX exporter into Prometheus and Grafana, with alerts on offline/under-replicated partitions, lag and disk.

An operator

Strimzi automates rolling updates, certificates, scaling and topic/user management declaratively in Kubernetes.
